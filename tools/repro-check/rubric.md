# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Environment matches target | Read the repro report's environment record against the issue context and the repo-facts block, using the Environment section of `references/evidence-guide.md`. | Pass when the report identifies enough relevant environment and version information to determine what was tested, and that environment matches the issue's stated target or any material difference is explicitly identified. Fail when missing or conflicting environment information prevents determining whether the reported result applies to the issue. | required |
| Steps are followable | Read the repro report's reproduction procedure against the issue context and use the Steps section of `references/evidence-guide.md`. | Pass when a stranger can reproduce the tested starting state, actions or commands, and trigger without having to guess a material action. Fail when a missing or ambiguous action prevents reaching the tested behavior. | required |
| Behavior matches issue | Read the repro report's artifacts such as output excerpts, logs, errors, or screenshots against the behavior described by the issue, using the Behavior shown section of `references/evidence-guide.md`. | Pass when a claimed successful reproduction has artifacts that demonstrate the material behavior at issue rather than a different or adjacent behavior. For an explicitly stated cannot-reproduce result, pass when the report records a concrete attempt, its observed result, and any material difference or limitation that could explain why the issue was not triggered; a cannot-reproduce does not need to prove the bug cannot occur or recreate a prerequisite the reporter explicitly says they could not achieve. Fail when a claimed successful reproduction lacks supporting evidence or demonstrates a materially different behavior, or when a cannot-reproduce conclusion lacks evidence of the attempt and observed result. | required |
| Outcome is honest | Compare the claim and conclusion in the repro report with its environment, steps, and artifacts, using the Honesty section of `references/evidence-guide.md`. | Pass when the stated outcome does not claim more than the evidence establishes. An evidenced cannot-reproduce passes when it accurately reports the attempted conditions and observed result. Fail when the package confidently claims reproduction, non-reproduction, cause, or scope that its evidence does not establish. | required |
| Repo conventions | Read the claim comment and repro report against the repo-facts block's bug-report, contribution, and AI-use requirements, using the Comms section of `references/evidence-guide.md`. | Pass when the comments satisfy every applicable requirement stated in the repo-facts block. Treat an explicit repository AI-use disclosure requirement mechanically: if repo facts say AI usage in issues or comments, or AI usage in any form, must be disclosed, the candidate package must contain that disclosure; if no disclosure appears, fail this check regardless of the technical quality of the reproduction. Do not require disclosure when repo facts explicitly say issue comments have no disclosure requirement. Also require the claim to identify the issue-specific investigation rather than generic boilerplate. Fail when any applicable repository requirement is violated. | required |
| Claim commitment | Read the claim comment against the issue context and the Path Review house rules in live mode, using the Comms section of `references/evidence-guide.md`. | Pass when the claim identifies the issue-specific investigation and commits to investigate and report findings without asserting unperformed reproduction, promising a fix, or promising a completion date. Fail when it falsely presents future work as completed or makes an unsupported promise. | required |

## Verdict rule

Accept only when every applicable required check passes. A `fail` on any applicable required check produces `reject`. An `unclear` grade on an applicable required check counts as a failure because the evidence needed to establish readiness is not verifiable. Preferred checks, if any are added later, never change the verdict. In live claim-only mode, checks that require a reproduction report are not yet applicable and are excluded from the verdict as specified by `SKILL.md`.
